# Contributing

Thanks for looking. This is a solo-maintained project, so the most useful thing
you can do before a large change is **open an issue first** — not as a
formality, but because I may already be halfway into the same file.

## Getting set up

```bash
npm install
npm run check     # lint + the full test suite. This is the gate CI applies.
```

The test suite needs **no PostgreSQL and no n8n instance**. The integration
tests boot the real server against a temporary SQLite file, which is deliberate:
it means CI passes in your fork without you provisioning anything.

To run the app against your own n8n, copy `.env.example` to `.env` and fill in
the six required variables. See
[documentation/deployment](documentation/deployment) for the full reference.

## Three things that are easy to get wrong

These are not style preferences. Each one silently ships something broken.

### 1. Never write `onclick=` — use `data-action`

The app serves a strict Content-Security-Policy including
`script-src-attr 'none'`, which blocks inline event handlers outright. An
`onclick` attribute will not throw at build time and will not fail a test; it
will simply do nothing in the browser.

Attach listeners in JavaScript, and use `data-action` attributes where a handler
needs to be found by markup.

### 2. Run `npm run build:css` after touching `input.css` — or any markup

Tailwind output is committed, and it is generated by scanning the HTML for class
names. **Adding a class to a template changes the CSS**, not just editing
`input.css`. Skip the rebuild and the app ships old CSS against new markup,
which reads as a broken upgrade rather than a missed step.

CI checks this and will tell you, but it is faster to just run it.

### 3. Run `node src/scripts/vendorAssets.js` after changing a browser dependency

There is no bundler. `public/vendor/` is committed and is what the container
actually serves — the Dockerfile installs dependencies before copying the
source, so nothing regenerates it at build time. CI enforces that it matches
`package.json`.

## Commits and branches

- `main` is always releasable. Work on `feat/<thing>` or `fix/<thing>` and open
  a PR.
- [Conventional Commits](https://www.conventionalcommits.org):
  `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `perf`, `build`, `ci`.

  ```
  feat(alerts): add Telegram channel
  fix(sync): handle n8n 2.1 execution_entity column rename
  docs(deployment): document the arm64 image
  ```

- Use `feat!:` or a `BREAKING CHANGE:` footer for anything in the table below.
  These are easy to ship by accident.

## What counts as breaking

This is a self-hosted app, so the version contract is about **upgrade safety**.
See [CHANGELOG.md](CHANGELOG.md).

| Bump | Means |
|---|---|
| MAJOR | An environment variable removed or renamed, an alert payload field changed, a manual migration step, or a raised minimum n8n / PostgreSQL version |
| MINOR | New features, new optional settings, new endpoints. A safe `docker compose pull`. |
| PATCH | Fixes only. Always safe. |

Two that are easy to miss:

- **The alert webhook `source` field.** People build n8n workflow filters on it.
  It is defined once, in `src/utils/alertValidation.js`, and changing it is a
  MAJOR bump.
- **Environment variable names.** Renaming one needs a deprecation path: read
  the old name, warn, and honour it for at least one release.

## Adding an endpoint

Routes → controllers → DAOs. All database access goes through a DAO; controllers
do not talk to the database directly. See
[documentation/backend](documentation/backend).

One trap worth knowing: every router under `/api` calls
`router.use(authenticateToken)` with **no path**, so it authenticates anything
reaching it — including a request that would have fallen through to a later
router. An endpoint that must be reachable without a token has to be declared
*above* those routers in `server.js`, not merely later in the file.
`/api/version` and the OAuth callback are the two that do this.

## Documentation

`documentation/` is the reference, one topic per folder, and it is expected to
